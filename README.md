## 🧭 简介

`job-journey` 把一次求职拆成八个可以单独调用、又能相互衔接的阶段：

1. 求职定位与目标定义；
2. 岗位发现、岗位池与初筛；
3. 公司、JD、岗位价值与风险分析；
4. 个人资料结构化与人岗逐项映射；
5. 简历与投递准备；
6. 面试准备与模拟面试；
7. 面试复盘与复试准备；
8. Offer 比较、谈薪与入职衔接。

Skill 会优先识别用户此刻真正要完成的主任务，只补齐必要前置分析，不会为了形式完整而每次强制运行八个阶段。用户也可以直接指定阶段。

阶段四“人岗逐项映射”是核心能力：Skill 从用户授权的简历、博客、作品集和补充说明中提取真实经历，再将岗位要求逐条映射到具体项目，区分直接匹配、可迁移匹配、待补强、关键缺口和待确认。

## ✨ 核心特点

- 🧩 **八阶段任务路由**：自动识别当前主任务，同时允许用户指定阶段。
- 📥 **多格式材料接入**：支持 PDF、Word、Excel、CSV、截图、网页链接和纯文本。
- 🧑‍💼 **个人资料跨岗位复用**：同一段真实经历可以为不同岗位突出不同能力，但不改变事实。
- 🔍 **人岗逐项映射**：岗位要求逐条关联到具体经历、项目、职责、行动和结果。
- 📊 **统一六维评分**：每项按 100 分展示，并同时给出可信度和一句判断。
- 🧱 **缺失材料不乱补**：没有个人资料时继续岗位侧分析，个人匹配保持“待确定”，不显示综合总分。
- 🧾 **来源与冲突保留**：OCR 不确定、网页失效、日期或职责冲突不会被静默覆盖。
- 🔐 **隐私优先**：默认最小读取、最小保存，不把个人敏感信息加入公开搜索请求。
- ✅ **经过评测**：八阶段完成无 Skill 基线与启用 Skill 对照，最终版本通过 44/44 项检查。

## 🎯 适用场景

### 推荐使用

- 想明确跳槽、转岗、职级或涨薪目标；
- 需要把多个 JD、截图或表格整理成岗位池并初筛；
- 想分析岗位职责、层级、价值、薪酬、公司业务和成长空间；
- 想判断个人与岗位的真实匹配关系，而不只是关键词相似；
- 需要针对某个岗位修改简历、投递消息或自我介绍；
- 需要准备一面、复试、模拟面试或面试追问；
- 想复盘面试逐字稿、录音转写或面试笔记；
- 需要比较 Offer、准备谈薪或制定入职 30/60/90 天计划。

### 不适合

- 招聘方批量筛选候选人或企业人才盘点；
- 与求职无关的通用公司研究；
- 替代律师、税务师或投资顾问提供持牌专业结论；
- 在没有可靠材料时预测确定的录用概率或所谓“公司真题”。

## ⚡ 快速开始

### 方式一：安装 `.skill` 包

1. 下载 [`dist/job-journey.skill`](dist/job-journey.skill)。
2. 在支持 `.skill` 文件的客户端中选择安装或导入。
3. 新建对话，直接描述当前求职任务。

可先校验安装包完整性：

```bash
shasum -a 256 -c dist/SHA256SUMS
```

### 方式二：从源码安装到 Codex

将仓库克隆到临时目录，再复制到 Codex Skills 目录：

```bash
git clone <你的 GitHub 仓库地址> /tmp/job-journey
mkdir -p ~/.codex/skills
cp -R /tmp/job-journey ~/.codex/skills/job-journey
```

安装后应能看到：

```text
~/.codex/skills/job-journey/SKILL.md
~/.codex/skills/job-journey/references/
```

如果目标目录已经存在，请先备份旧版本，不要直接覆盖个人修改。

### 第一次测试

```text
我还没有完整简历，先把这批岗位整理成岗位池并做初筛。个人匹配先标记待确定。
```

## 🛠️ 使用方法

### 直接描述主任务

不需要记住命令，使用自然语言即可：

```text
分析这个 AI 产品经理岗位。先做岗位分析，我暂时不提供个人简历。
```

```text
把我的简历和这个 JD 做逐项映射。没有材料证明的能力标记待确认，不要猜测。
```

```text
我明天下午有业务一面，请结合当前 JD 和简历准备问题、项目回答和可能的追问。
```

```text
根据这份面试逐字稿做复盘，并帮我整理下一轮要补强的内容。
```

```text
比较这两个 Offer。分别拆解薪酬、岗位价值、成长性和稳定性，再给出谈薪清单。
```

### 明确指定阶段

如果你只需要某一部分，可以直接说明：

```text
只执行阶段四：人岗逐项映射。暂时不要修改简历。
```

### 组合材料

同一次任务可以混合提供：

- 岗位 JD 的 PDF、Word、截图、链接或文本；
- 岗位池 Excel/CSV；
- 简历 PDF/Word；
- 个人博客、作品集和项目文档；
- 面试逐字稿、笔记或 Offer 文件。

对不可访问的链接或无法辨认的截图，Skill 会请求粘贴正文、重新导出文件，或只确认会改变结论的关键字段。

## ❓ FAQ

### 1. 每次都会执行完整八阶段吗？

不会。Skill 优先完成当前主任务，只补齐不可缺少的前置分析，不自动延伸到无关后续阶段。

### 2. 没有简历还能使用吗？

可以。岗位发现和岗位分析可以继续；个人匹配会显示“待确定”，综合总分不会显示，也不会把缺失项按 0 分计算。

### 3. Skill 会自动保存我的简历吗？

不会默认持久化。只有用户明确要求建立或更新个人资料时，才会在说明保存内容和路径后写入用户选择的工作区。运行时数据不得写入 Skill 安装目录。

### 4. 支持哪些文件？

支持 PDF、DOCX、XLSX、CSV、截图、网页链接和纯文本。扫描件和截图可能需要 OCR，低置信字段会保留并请求确认。

### 5. 为什么没有综合总分？

综合总分只有在六个维度都有有效得分时才显示。个人资料、薪酬结构或公司信息不足时，只展示可确认的单项分数和待补材料。

### 6. 分数是录用概率吗？

不是。分数用于在统一口径下比较岗位和匹配关系，不代表面试通过率或录用概率。

### 7. 面试题是某公司的历史真题吗？

不是。题目来自 JD、个人材料和内置面试方法的语义匹配，除非用户提供可靠来源，否则不会宣称为某家公司真实历史题。

### 8. 会把个人信息用于公开搜索吗？

不会把手机号、邮箱、身份证号、详细住址、精确薪酬或完整面试逐字稿加入公开搜索请求。联网检索只使用完成任务所需的公开关键词。

### 9. 这是“职途 AI”网页版产品吗？

不是。本仓库是可独立安装的 `job-journey` Skill。由它延展的“职途 AI”产品拥有独立的产品方案、数据和网页代码，不包含在本 Skill 包中。

### 10. 可以直接同步整个开发工作区到 GitHub 吗？

不建议。公开仓库应使用本发布目录；内部 `workspace/` 可能包含大量运行输出，不属于安装包。同步前仍应检查仓库中是否误放真实简历、岗位材料或个人数据。
